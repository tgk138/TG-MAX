# Продуктизация TG→MAX

## Проблема

Проект TG→MAX был технически готов (миграция Telegram → MAX), но не оформлен как продукт: не было чёткого ценностного предложения, лендинга, доверия (Terms, Privacy, Support), фавиконки и мета-тегов, футера и README.

## Решение

Проведена продуктизация в духе Compound Engineering: параллельно закрыты лендинг, бренд/мета, доверие и документация.

### 1. Лендинг (главная страница)

- **Hero:** теглайн «Сервис миграции контента», заголовок «Из Telegram — в MAX», короткое описание и CTA «Начать бесплатно».
- **Блок «Зачем использовать»:** без кода, сохранение структуры, один поток импорта/публикации.
- **Блок «Как это работает»:** нумерованные шаги + повторный CTA.

Файл: `src/app/templates/home.html`.

### 2. Бренд и мета

- **Favicon:** маршруты `/favicon.ico` (редирект) и `/favicon.svg` (SVG с логотипом TG), чтобы убрать 404 в логах.
- **Meta:** `description`, `og:title`, `og:description`, `og:type`, `twitter:card`, `twitter:title` в `base.html`.
- **Футер:** блок «TG→MAX» с ссылками на Пользовательское соглашение, Конфиденциальность, Поддержка.

Файлы: `src/app/templates/base.html`, `src/app/main.py` (роуты фавикона).

### 3. Доверие (Legal & Support)

- Страницы **Пользовательское соглашение** (`/terms`), **Конфиденциальность** (`/privacy`), **Поддержка** (`/support`) с понятным текстом-заполнителем и FAQ по коду Telegram / токену MAX.
- Роуты и шаблоны: `api/pages.py`, `templates/terms.html`, `privacy.html`, `support.html`.

### 4. README

- Описание продукта, возможности, стек, быстрый старт (venv, pip, .env), запуск локально и через Docker, конфигурация, структура проекта, ссылки на Terms/Privacy/Support.

Файл: `README.md` в корне.

## Итог

- Один файл лендинга, один базовый шаблон с мета и футером, три страницы доверия, два маршрута фавикона, один README.
- Продукт выглядит оформленным: есть ценность на главной, доверие в футере, фавикон в табах, описание в поиске и соцсетях.

## Предотвращение

- При добавлении новых страниц подключать `base.html` и при необходимости блоки `meta_description` / `og_title`.
- Новые публичные страницы сразу добавлять в футер или навигацию, если они важны для продукта.
